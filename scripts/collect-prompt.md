# 일일 브리핑 수집 지시서

너는 매일 아침 4개국의 주요 뉴스를 수집해 `data/issues.json`을 갱신한다.
**수정할 파일은 `data/issues.json` 하나뿐이다.** 다른 파일은 절대 건드리지 않는다.

## 대상

한국(KR), 미국(US), 중국(CN), 일본(JP). 각 국가마다 정치 2건, 경제 2건, 기타 2건 — 총 6건씩, 전체 24건.

## 작업 순서

**1단계 이슈 탐색 → 2단계 related 확보 → 3단계 정제 및 저장.**
단계를 건너뛰거나 섞지 않는다. 2단계를 마치기 전에 파일을 쓰지 않는다.

---

# 0단계 — 기존 파일 읽기

`data/issues.json`을 읽는다. 다음 두 가지를 반드시 파악한다.

- 각 국가의 `latestDate` — 새로 넣을 날짜가 이보다 뒤인지 확인한다. 같거나 이전이면 그 국가는 건너뛴다.
- **기존에 쓰인 `topics` 키워드 전체 목록** — 모든 국가, 모든 기사의 `topics` 값을 모아 둔다. 3단계에서 쓴다.

---

# 1단계 — 이슈 탐색

WebSearch로 각 국가의 **지난 24시간** 주요 뉴스를 찾는다.

- 정치 · 경제 · 기타(사회·과학·기술·환경 등) 각 2건씩 고른다.
- 그 나라에서 실제로 비중 있게 다뤄진 사안을 고른다. 한국 독자가 국제 정세를 이해하는 데 도움이 되는 것을 우선한다.
- 연예·스포츠·사건사고 단신은 제외한다.
- 출처 URL은 **검색 결과에 실제로 나온 것만** 쓴다. 절대 지어내지 않는다. 확인되지 않으면 그 기사를 버리고 다른 기사를 고른다.

## 검색 결과를 버리지 마라

한 이슈를 검색하면 보통 여러 매체의 기사가 함께 나온다.
**그중 대표 기사 하나만 `sources`에 넣고, 나머지는 버리지 말고 손에 들고 2단계로 넘어간다.**
2단계에서 `related` 후보로 쓴다.

---

# 2단계 — related 확보

**모든 기사는 `related`를 하나씩 가져야 한다.** 이 단계는 그것만 처리한다.

## 순서

1. **1단계에서 이미 확보한 다른 매체 기사를 먼저 배정한다.** 대부분 여기서 끝난다.
   같은 이슈를 다룬 다른 매체 기사가 있으면 추가 검색 없이 그대로 쓴다.
2. 후보가 없을 때만 **그 이슈에 대해 한 번 더 검색한다.**
   이때는 `"<이슈 핵심어> 비판"`, `"<이슈 핵심어> 반론"`처럼 **다른 시각**을 겨냥해 검색한다.
3. 그래도 못 찾으면 `related`를 생략한다. **지어내는 것보다 비우는 편이 낫다.**

## 어떤 기사를 고를 것인가

`type`은 `유사`(같은 논조) / `반박`(같은 주제, 다른 의견) / `다름`(주장하는 사실 자체가 다름) 중 하나다.

- **`반박`과 `다름`을 우선한다.** 독자가 한쪽 논조만 보게 되는 것이 이 필드가 막으려는 문제다.
- `유사`만 잔뜩 붙으면 이 필드는 의미가 없다. **전체 24건 중 `유사`가 절반을 넘지 않게 한다.**
- `sources`에 넣은 기사와 **다른 매체**여야 한다. 같은 매체의 후속 기사는 쓰지 않는다.
- 반드시 실제 존재하는, 검색 결과에서 확인된 기사여야 한다.

---

# 3단계 — 정제 및 저장

## 기사 객체 만들기

```json
{
  "id": "kr-pol-20260811-1",
  "date": "2026.08.11",
  "category": "politics",
  "categoryLabel": "정치",
  "title": "기사 제목",
  "summary": "결론부터 한두 문장. Answer First.",
  "why": "왜 지금 이 일이 벌어졌는가. 한 문장.",
  "soWhat": "앞으로 무엇이 달라지는가. 한 문장.",
  "context": {
    "background": "이 사안의 기존 경위. 한두 문장.",
    "issueContext": "지금 무엇이 문제인가. 한두 문장.",
    "coreQuestion": "핵심 질문. 반드시 '~까요?'로 끝낸다.",
    "resolution": "현재 어떻게 정리되었는가. 한두 문장."
  },
  "sources": [{ "name": "매체명", "url": "https://..." }],
  "related": {
    "title": "함께 읽으면 좋은 기사 제목",
    "source": "매체명",
    "url": "https://...",
    "type": "반박"
  },
  "topics": ["반도체", "세액공제", "국회", "투자"],
  "review": "pending"
}
```

### 필드 규칙

| 필드 | 규칙 |
| --- | --- |
| `id` | `<국가소문자>-<pol\|eco\|oth>-<YYYYMMDD>-<번호>`. 기존 id와 절대 겹치면 안 된다. |
| `date` | `YYYY.MM.DD`. KST 기준 오늘 날짜. |
| `category` | `politics` / `economy` / `other` 중 하나. `categoryLabel`은 각각 `정치` / `경제` / `기타`. |
| `summary` | **결론부터.** 배경 설명으로 시작하지 않는다. 두 문장을 넘기지 않는다. |
| `coreQuestion` | 반드시 `~까요?`로 끝나는 의문문. 양자택일이면 "A일까요, B일까요?" 형태로 쓴다. |
| `sources` | **대표 기사 1건만 넣는다.** 같은 이슈의 다른 매체 기사는 `sources`에 추가하지 말고 `related`로 보낸다. 대표 기사를 단독으로 확정하기 어려울 때만 예외적으로 2건까지 허용한다. |
| `related` | 2단계에서 확보한 기사. `type`은 `유사` / `반박` / `다름` 중 하나. |
| `review` | 항상 `"pending"`. 사람이 검수한 뒤 손으로 `"ok"`로 바꾼다. |

### topics — 가장 중요한 규칙

`topics`는 화면의 이슈 관계도에서 **기사를 서로 잇는 유일한 근거**다. 이것이 어긋나면 매일 고립된 점만 쌓이고 그래프가 무의미해진다.

- 명사 키워드 3~5개.
- **0단계에서 모아 둔 기존 키워드 목록을 먼저 확인하고, 의미가 같으면 반드시 그 단어를 그대로 쓴다.**
  - 예: 기존에 `금리`가 있으면 `기준금리`나 `이자율`이라고 새로 만들지 않는다.
  - 예: 기존에 `반도체`가 있으면 `세미컨덕터`라고 쓰지 않는다.
- 기존 목록에 없는 새 개념일 때만 새 단어를 만든다.
- 국가가 달라도 같은 주제면 같은 키워드를 쓴다. (미국의 `금리`와 일본의 `금리`는 같은 단어여야 한다.)
- 너무 일반적인 단어(`뉴스`, `사회`, `정부`)는 쓰지 않는다. 모든 기사에 붙어 그래프가 뭉개진다.

## 파일 갱신

각 국가 `COUNTRIES.<코드>`에 대해:

1. 새 기사 6건을 `issues` 배열 **맨 앞**에 추가한다. 기존 항목은 하나도 지우지 않는다.
2. `latestDate`를 오늘 날짜로 바꾼다.
3. `period`를 `"어제날짜 08:00 ~ 오늘날짜 08:00"` 형식으로 바꾼다.
4. `updatedAt`을 `"오늘날짜 08:00 KST"`로 바꾼다.
   **4개국 모두 `KST`로 통일한다.** 미국이라고 `EST`, 일본이라고 `JST`로 쓰지 않는다.
   이 화면은 한국 독자를 위한 것이고 시간대가 섞이면 비교가 불가능해진다.

들여쓰기 2칸 JSON으로 저장한다. `SUPPORTED_COUNTRIES`는 건드리지 않는다.

## 저장 전 검증

아래 중 **하나라도 어긋나면 파일을 저장하지 말고 그대로 종료한다.** 잘못된 데이터를 올리는 것보다 어제 데이터를 유지하는 편이 낫다.

- [ ] JSON 문법이 유효한가
- [ ] 모든 `id`가 파일 전체에서 유일한가
- [ ] 필수 필드가 하나도 빠지지 않았는가 (`context` 4개 항목 포함)
- [ ] 모든 `url`이 검색 결과에서 실제로 확인된 주소인가
- [ ] `category` 값이 세 가지 중 하나인가
- [ ] `coreQuestion`이 `~까요?`로 끝나는가
- [ ] 기존 기사가 하나도 삭제되지 않았는가
- [ ] **`sources`가 기사당 1건인가** (예외 허용 시에도 2건 이하)
- [ ] **모든 기사에 `related`가 있는가** — 없는 기사가 있으면 그 목록을 세고, 2단계로 돌아가 다시 시도한다
- [ ] **`related`의 `type`이 `유사`인 기사가 전체의 절반을 넘지 않는가**
- [ ] **모든 `updatedAt`이 `KST`로 끝나는가**

검증을 마치면 **어긋난 항목이 없음을 확인했다고 명시적으로 보고한 뒤** 저장한다.

## 하지 말 것

- 기사 **전문을 복사해 넣지 않는다.** 요약과 링크만 둔다. 저작권 문제가 된다.
- 검색으로 확인되지 않은 사실을 지어내지 않는다. 6건을 못 채우면 채운 만큼만 넣는다.
- `data/flashes.json`은 건드리지 않는다. 속보는 사람이 직접 넣는다.
- 코드 파일(`.dc.html`, `.js`)은 어떤 경우에도 수정하지 않는다.
